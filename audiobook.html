GitHub Copilot. Guia de estudo para a certificação G H trezentos.

Neste áudio, os principais conceitos do exame são apresentados em dez capítulos, organizados por tema: como o Copilot funciona, planos e cobrança, engenharia de prompt, o Chat, comandos, recursos do Enterprise, gestão, segurança, ética e o ciclo de desenvolvimento de software. Vamos começar.

Capítulo 1

Como o GitHub Copilot Funciona

O GitHub Copilot é um assistente que ajuda a escrever código, e há mais de uma forma de interagir com ele. Uma delas é diretamente pelo navegador, acessando github ponto com. O serviço de proxy do Copilot é hospedado no Microsoft Azure.

Para sugerir algo útil, o Copilot depende de contexto. No I D E, ele usa informações como as abas abertas, a posição do cursor e o código selecionado. O modelo de linguagem, o L L M, também deriva contexto de arquivos vizinhos ou relacionados dentro do projeto. No Copilot Chat, existe ainda uma etapa de pré-processamento da entrada do usuário, que enriquece o prompt com contexto adicional antes de passá-lo ao modelo de linguagem. Entre as etapas do ciclo de vida de uma sugestão estão capturar o contexto do usuário e gerar a sugestão. A técnica Fill in the Middle, ou F I M, melhora as sugestões ao considerar tanto o prefixo quanto o sufixo do código, preenchendo a parte intermediária com mais precisão.

Como foi treinado em padrões de código comumente usados, o Copilot tende a sugerir trechos que refletem as práticas mais comuns nos dados de treinamento. O Copilot Chat, por sua vez, se baseia principalmente nos dados de treinamento do modelo para gerar o que devolve ao usuário. Por isso, o Copilot pode sugerir sintaxe ou recursos obsoletos, se eles estiverem presentes nesses dados.

Na prática, o Copilot aumenta a produtividade ao automatizar tarefas repetitivas de codificação. E quando as sugestões de código não aparecem no editor, os motivos possíveis são: não haver uma conexão ativa com a internet, a linguagem de programação não ser suportada, ou não haver uma licença válida do GitHub Copilot.

Capítulo 2

Planos, Preços e Cobrança

O GitHub Copilot Individual é cobrado de duas formas: mensalmente, como assinatura, ou anualmente, também como assinatura. Para quem trabalha em projetos de código aberto, o pagamento pode ser feito por fatura ou cartão de crédito. O Individual é o plano indicado para um contratante independente que desenvolve aplicativos para diversos clientes. Uma organização do Azure DevOps também pode usá-lo, sem precisar de uma licença do GitHub Enterprise. Quanto aos dados, o Individual usa os dados de prompt para treinar modelos de aprendizado de máquina, em busca de sugestões de código melhores, e a entrada do usuário em tempo real ajuda a gerar sugestões sensíveis ao contexto. Ao usar uma extensão compatível para Visual Studio, V S Code ou I D Es da JetBrains, ficam disponíveis as sugestões de código e o Chat.

Quando a equipe usa o Individual e precisa de recursos administrativos e de exclusão de conteúdo, o caminho é atualizar para o Copilot Business. O Business também é o plano para uma empresa que guarda seu código no Bitbucket e quer usar o Copilot, no caso de clientes que não usam o G H E.

Tanto o Business quanto o Enterprise incluem recursos que excluem os dados de uso, os prompts e as sugestões do treinamento padrão do GitHub Copilot. Nesses dois planos, o GitHub retém prompts e sugestões por 28 dias, e os dados de engajamento do usuário por 2 anos.

O plano que permite a coleta de solicitações e sugestões é o Copilot Enterprise. É também o plano que dá acesso às bases de conhecimento da empresa.

Capítulo 3

Engenharia de Prompt

A qualidade do que o Copilot sugere depende bastante de como o prompt é escrito. Duas técnicas para melhorá-lo são fornecer critérios de sucesso específicos e informar onde obter o conteúdo necessário. As práticas que melhoram a qualidade das sugestões incluem definir claramente o problema ou a tarefa, usar nomes de variáveis significativos e fornecer exemplos dos resultados desejados. Aplicar técnicas de engenharia de prompt para ser mais específico é também uma estratégia para aumentar o desempenho do Copilot Chat.

Existem estilos de prompt com nomes próprios. No zero shot prompting, ou prompt de disparo zero, basta apresentar o pedido ao Copilot, sem nenhum exemplo. No few shot prompting, ou prompt de poucos disparos, o desenvolvedor informa o mecanismo que quer usar e como incorporá-lo ao resultado, fornecendo exemplos. Já no role prompting, descreve-se no prompt qual é a função de quem pede, para obter uma sugestão melhor.

Os exemplos também ajudam a alinhar o resultado às necessidades. Para que o Copilot Chat gere código de teste seguindo os padrões da empresa, o caminho é usar exemplos de prompts específicos na própria solicitação. E, para aumentar a relevância do código gerado, a estratégia recomendada é incluir no prompt exemplos de entrada e de saída esperadas.

Capítulo 4

GitHub Copilot Chat

O Copilot Chat é uma ferramenta de produtividade que dá sugestões, mas conta com o julgamento humano. Por isso, ao confiar em suas explicações sobre o funcionamento do código e as melhorias propostas, a principal consideração é revisar e validar o que foi gerado, quanto à precisão e à integridade. Entre suas possíveis limitações estão os dados de treinamento limitados e a capacidade restrita de lidar com estruturas de código complexas.

Ele é especialmente útil para entender código. Ajuda a compreender uma base de código existente tirando dúvidas sobre o código e gerando explicações. É eficaz para explicar um código Cobol legado e traduzi-lo para outra linguagem, como C sharp, e para criar um cenário de teste de unidade para um código Python recém-desenvolvido. Também aumenta a produtividade quando um desenvolvedor é adicionado a um novo projeto e precisa entender o código do software atual, ou quando é preciso criar um arquivo de documentação para uma base de código recém-criada. Para quem está aprendendo uma nova linguagem, o Chat orienta e apoia nas tarefas e desafios comuns de codificação nessa linguagem, e o Copilot pode converter comentários em código, o que ajuda a compreender a sintaxe e as nuances dela. Dentro de um I D E com um plugin compatível do GitHub Copilot, o Chat pode gerar testes unitários, explicar o código e sugerir melhorias. Para garantir que uma função funcione corretamente, o Chat sugere asserts, ou afirmações, baseadas no contexto e na semântica do código.

Para obter retornos mais precisos, é preciso dar contexto. Isso pode ser feito com participantes do chat, como arroba workspace, que incorporam contexto colaborativo, e com variáveis de chat, como hashtag file e hashtag editors, que ancoram a conversa no contexto específico dos arquivos ou editores em uso. Também melhora o contexto abrir as abas relevantes no I D E e adicionar ao prompt os caminhos completos dos arquivos importantes. O histórico do chat tem um papel importante: ele fornece contexto ao Copilot, melhorando a relevância e a precisão das sugestões de código, e é usado para oferecer trechos de código personalizados com base em solicitações anteriores.

Capítulo 5

Comandos de Barra, CLI e Sugestões

Os comandos de barra dão atalhos para tarefas comuns no Chat. O comando barra tests cria testes de unidade para o código selecionado, e é o comando a usar ao gerar testes de unidade com o Chat. O comando barra optimize, no Visual Studio, melhora o desempenho do código selecionado analisando sua complexidade de tempo de execução. E o comando barra fix propõe alterações para problemas detectados, sugerindo correções para erros de sintaxe e erros de programação. Para obter sugestões integradas de refatoração, pode-se também adicionar comentários ao código e acionar uma sugestão, ou usar o comando barra fix no chat em linha do GitHub Copilot.

Na interface de linha de comando, a C L I, para gerar sugestões de código usa-se G H copilot suggest, escreve-se o comando desejado e, em seguida, seleciona-se a melhor sugestão da lista. O Copilot na C L I também permite definir a confirmação de execução padrão e a análise de uso.

Nos editores, para ver várias sugestões, abre-se o painel de conclusões. Outras sugestões de código podem ser mostradas em uma nova guia, e atalhos de teclado permitem aceitar a próxima palavra de uma sugestão.

Por fim, o feedback sobre o Copilot Chat pode ser dado de duas formas: no I D E, pelo botão Compartilhar feedback no painel do Chat, e no GitHub Mobile, pelos emojis na interface do Chat.

Capítulo 6

Copilot Enterprise: Recursos Avançados

O Copilot Enterprise reúne recursos avançados. Em todos os I D Es com suporte comercial, estão disponíveis as sugestões embutidas, as chamadas sugestões inline. As bases de conhecimento, as knowledge bases, são um recurso exclusivo do plano Enterprise, e podem tirar dúvidas sobre trechos de código, documentação e padrões de design. Com os modelos personalizados, o Copilot produz retornos que usam as práticas e os padrões dos repositórios da própria organização. Nas revisões de código durante o processo de pull request, o Enterprise gera um resumo em prosa e uma lista com marcadores das principais alterações de todas as pull requests, e também pode tirar dúvidas sobre o conjunto de alterações.

Capítulo 7

Gestão: Políticas, Exclusões e Auditoria

A gestão do Copilot em uma organização passa por políticas, exclusões de conteúdo, auditoria e métricas. Para restringir o uso do Copilot Business a determinados repositórios, a política em toda a organização é configurada nas configurações da organização.

Sobre as exclusões de conteúdo: podem ser configurados para exclusão arquivos, pastas e repositórios. Para excluir arquivos específicos do uso do Copilot Business, eles são adicionados a um arquivo copilot ponto ignore. O conteúdo excluído deixa de estar disponível diretamente para o Copilot como contexto, e as sugestões do Copilot não aparecem mais nos arquivos excluídos. Ainda assim, o Copilot pode usar conteúdo excluído se o conteúdo de um arquivo excluído for referenciado em código que não foi excluído, por exemplo, em chamadas de função. Uma limitação das exclusões é que elas podem ser contornadas, pois estão disponíveis apenas para repositórios Git. A exclusão de conteúdo leva até 30 minutos para ser adicionada ou atualizada. Se as exclusões não estiverem funcionando, deve-se verificar se o usuário está em uma organização que tem exclusões de conteúdo configuradas, e se as configurações de exclusão de conteúdo foram alteradas nos últimos 30 minutos ou antes disso. Para validar que o Copilot não está retornando sugestões por causa das exclusões, o ícone do GitHub Copilot na barra de status do editor exibe uma mensagem.

Na auditoria, os eventos de log de auditoria do Copilot Business são acessados pela seção Log de auditoria, nas configurações do GitHub da organização. O objetivo principal dos logs de auditoria da organização é monitorar atividades e ações do administrador dentro da organização. Entre as atividades que podem ser rastreadas estão as sugestões de código feitas pelo GitHub Copilot e as mudanças nas configurações de exclusão de conteúdo.

Quanto às métricas, a A P I de métricas de uso pode rastrear o número de sugestões de código aceitas e usadas na organização, e também fornecer métricas de aceitação de sugestões específicas do Copilot Chat. Esses insights mostram, por exemplo, em quais linguagens de codificação o Copilot é mais útil, e assim ajudam a melhorar o processo de desenvolvimento. Já a A P I Rest permite, para as assinaturas do Copilot Business, listar todas as atribuições de licença de uma organização e obter um resumo do uso do Copilot pelos membros da organização. Para modificar detalhes de uma assinatura do Copilot Business, os endpoints da A P I Rest permitem adicionar equipes à assinatura do Copilot de uma organização e remover equipes dessa assinatura.

Capítulo 8

Segurança, IP e Código Público

Um tema central de segurança é o código público. O filtro de detecção de duplicação do Copilot pode ser configurado no nível da organização para evitar que o Copilot sugira trechos de código disponíveis publicamente. O objetivo principal do filtro é detectar e bloquear sugestões que correspondam a trechos de código público no GitHub, se contiverem cerca de 150 caracteres. O processo funciona executando as sugestões de código por meio de filtros projetados para detectar código público. Além disso, o Copilot filtra sugestões que correspondam ao código de repositórios públicos e implementa salvaguardas para detectar e evitar a sugestão de trechos literais de código público. Antes de a sugestão chegar ao usuário, há verificações adicionais: a correspondência com código público, opcional conforme as configurações, e a compatibilidade com configurações específicas do usuário. Para configurar a detecção de duplicatas, há dois caminhos: Configurações empresariais, depois Copilot, depois Políticas; ou Configurações da organização, depois Copilot, depois Políticas.

Para ter a ajuda da Microsoft e do GitHub na proteção contra violação de I P, é preciso bloquear as correspondências de código público: a configuração de sugestões que correspondem ao código público deve ser definida como bloqueado.

O filtro de toxicidade do Copilot pode sinalizar prompts ou trechos de código com discurso de ódio ou linguagem discriminatória, como insultos raciais e estereótipos ofensivos, e também conteúdo sexualmente sugestivo ou explícito. Garantir a segurança do código usado em ferramentas de I A generativa evita acesso não autorizado e possíveis violações de dados. E o Copilot Chat ajuda a corrigir problemas de segurança na base de código anotando as sugestões que fornece com padrões de vulnerabilidade conhecidos.

Capítulo 9

Ética e IA Responsável

O uso responsável da I A começa por entender seus riscos. Um deles é que os sistemas de I A podem, por vezes, tomar decisões difíceis de interpretar. Outro é a imprecisão: uma ferramenta de I A generativa pode criar resultados imprecisos porque os dados de treinamento podem conter preconceitos ou inconsistências. Para minimizar preconceitos durante o desenvolvimento da I A, usam-se dados diversos, métricas de justiça e supervisão humana. O desenvolvedor também deve ter cuidado ao usar o Copilot para cálculos matemáticos, evitando depender de retornos baseados em padrões sem verificar a precisão do cálculo.

Entre os princípios éticos de I A da Microsoft, a justiça, ou Fairness, visa garantir que os sistemas de I A tratem todas as pessoas igualmente. Na operação de uma ferramenta de I A, a justiça pode ser integrada treinando dados e algoritmos de I A para serem livres de preconceitos. Já a transparência é o princípio que enfatiza que os sistemas de I A devem ser compreensíveis e fornecer informações claras sobre como funcionam. Um exemplo: um gerente de mídia social que quer usar I A para filtrar conteúdo aplica a transparência ao fornecer explicações claras sobre os tipos de conteúdo que a I A foi projetada para filtrar e sobre como ela chega à sua conclusão.

Capítulo 10

SDLC: Desenvolvimento, Testes e Produtividade

O Copilot pode ajudar em cada fase do Ciclo de Vida de Desenvolvimento de Software, o S D L C. Na análise de requisitos, ele fornece modelos e trechos de código que auxiliam na documentação dos requisitos. Na fase de design, pode sugerir padrões de design e práticas recomendadas relevantes para o projeto.

Na escrita do código, o Copilot ajuda os desenvolvedores a reduzir a quantidade de código padrão, o boilerplate, que precisam escrever manualmente, sugerindo trechos de código que podem ser reutilizados em diferentes partes do projeto. Também sugere otimizações para melhorar o desempenho, analisando a base de código e sugerindo algoritmos ou estruturas de dados mais eficientes. Ajuda a escrever documentação, sugerindo resumos ou descrições com base na funcionalidade do código. E reduz a alternância de contexto, porque permite que os desenvolvedores permaneçam no I D E. Na modernização de aplicativos, o Copilot pode sugerir padrões de programação modernos com base no código do desenvolvedor. Para gerar dados de amostra, um método é usar a capacidade do Copilot de criar informações fictícias a partir de padrões nos dados de treinamento; outro é aproveitar suas sugestões para criar dados com base na documentação da A P I no repositório.

Na refatoração, o Copilot pode sugerir melhorias para uma melhor qualidade de código, fornecendo sugestões para melhorar a legibilidade e a manutenção com base nas melhores práticas e oferecendo exemplos de transformação de código que melhoram o desempenho e reduzem a complexidade. Para orientar o Copilot Chat nessa tarefa, servem prompts como pedir que mostre como melhorar a legibilidade de uma função, ou que sugira maneiras de melhorar a capacidade de manutenção de um trecho de código. Há, porém, limitações: o Copilot nem sempre produz código otimizado ou alinhado às melhores práticas de refatoração. Uma boa prática é revisar e refatorar regularmente o código sugerido pelo Copilot.

Nos testes, o Copilot ajuda a manter a consistência identificando um padrão na maneira como o desenvolvedor escreve testes e sugerindo padrões semelhantes para testes futuros. Para identificar testes ausentes na base de código, o fator mais importante é garantir que o contexto correto do projeto esteja disponível para o Copilot. Mas há limites: ele sugere principalmente testes de unidade básicos, focados nas funcionalidades principais, muitas vezes exigindo informações adicionais dos desenvolvedores para uma cobertura abrangente. Por isso, a revisão de código continua necessária, porque os casos de teste gerados podem não cobrir todos os cenários possíveis.

Quem depende muito do código gerado corre riscos: o Copilot pode introduzir vulnerabilidades de segurança ao sugerir código com explorações conhecidas, e suas sugestões nem sempre refletem as práticas recomendadas ou os padrões de codificação mais recentes. Em análises estatísticas, é preciso lembrar que as sugestões se baseiam em tendências estatísticas e nem sempre se aplicam com precisão a conjuntos de dados específicos. E, na manutenção de bases de código existentes, o Copilot pode não compreender totalmente o contexto e as dependências de uma base de código grande.
